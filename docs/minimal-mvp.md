# Minimal game starting point

Open project.godot in Godot 4.7.2 and press F5. Move with WASD or arrow keys.
The ship stays centered. The player moves around the deck and cannot cross its outer boundary.

## Scenes and scripts

- scenes/main.tscn: ship instance and fixed camera. The project background color supplies the blue ocean.
- scenes/ship.tscn: one ship Sprite2D, a deck boundary collider, a Gangplank trigger area, and an instance of the player scene.
- scenes/player.tscn: a CharacterBody2D, a static Viking Sprite2D, and a circular feet collider.
- scenes/island.tscn: a Sprite2D using real island artwork, a fixed camera, an island boundary collider traced to the artwork's coastline, a player instance, three Coconut instances, a Rowboat trigger area, and a HUD (coconut count, countdown timer, and a pirate-ship progress track).
- scenes/coconut.tscn: a collectible Area2D with a placeholder sprite and a "collected" signal.
- scripts/player.gd: reads input, sets velocity, and calls move_and_slide().
- scripts/coconut.gd: detects the player walking over a coconut, emits "collected", and removes itself.
- scripts/island.gd: the island's run logic. Counts coconuts, runs the countdown timer, moves the pirate-ship HUD icon along its track as time passes, and decides win/lose when the player reaches the rowboat or the timer hits zero.
- scripts/rowboat.gd: detects the player reaching the rowboat and asks island.gd's try_escape() to decide whether that succeeds.
- scripts/scene_trigger.gd: a reusable walk-over trigger (Area2D) that switches to whatever scene is set in its Inspector "Target Scene" field. Used by the ship's Gangplank to go to scenes/island.tscn.
- assets/ship.png and assets/player_viking.png: transparent PNG artwork. No shaders or animation are needed.
- assets/island.png: the island artwork (618x584). scenes/island.tscn's Sprite2D uses it at 1:1 scale, centered on the scene origin. IslandBoundary/CollisionPolygon2D's 26 points were generated by color-thresholding the art into land/water and tracing the coastline (including the dock and the small bridge-connected island), then simplified and inset a few pixels so the player doesn't visually clip the shoreline. It is not pixel-perfect around fine detail (e.g. the small interior pond is not carved out as a separate obstacle) and can be refined by hand in the 2D viewport like any other CollisionPolygon2D.
- The coconuts, rowboat hull, and pirate-ship HUD icon still use simple colored Polygon2D shapes as placeholder art, per AGENTS.md, until real artwork exists for them too.

The wheel, lanterns, and grates are painted into the ship image; they are not interactive nodes.

## Island run: coconuts vs. the pirate ship

Stepping onto the island (via the ship's Gangplank) starts a run:

- Collect all three coconuts, shown in the top-left HUD as "Coconuts: x / 3".
- A countdown ("Time left: Xs") and a pirate-ship icon sliding across a track represent the same underlying timer (island.gd's time_limit_seconds, 60 seconds by default, tunable in the Inspector on the Island node) — the icon reaches the end of the track exactly when time runs out.
- Walk into the Rowboat near the bottom of the island. If all coconuts are collected, you win and are sent back to scenes/ship.tscn. If coconuts remain, a message reminds you and the timer keeps running.
- If the timer reaches zero before you escape with all the coconuts, a "the pirate ship reached the island" message appears and the island scene reloads so you can try again.

This is intentionally simple: no actual pirate ship sails across the ocean yet, no lives/score system, and losing just restarts the same island. Treat those as natural next steps, not gaps in this pass.

## Inspect it in Godot

1. In the FileSystem dock, double-click scenes/main.tscn to see the assembled game.
2. Double-click scenes/ship.tscn to inspect the ship artwork, DeckBoundary, and Player instance in the Scene dock.
3. Double-click scenes/player.tscn and select Player. Change Walk Speed in the Inspector to adjust movement speed.
4. Open scripts/player.gd to read the movement code. Input.get_vector reads the four movement actions; velocity sets speed; move_and_slide handles movement and collision.
5. To see the key bindings, choose Project > Project Settings, then the Input Map tab.
6. To edit the walkable boundary, open scenes/ship.tscn and select DeckBoundary/CollisionPolygon2D. Edit its vertices in the 2D viewport. Keep Build Mode set to Segments so only the perimeter blocks movement.
7. Walk the player onto the Gangplank near the bottom of the ship deck to switch to scenes/island.tscn.
8. On the island, collect all three coconuts and walk into the Rowboat before the countdown (and the pirate-ship icon on its track) reaches the end. Reaching the rowboat with all coconuts sends you back to scenes/ship.tscn; running out of time reloads the island so you can try again.
9. Open scenes/island.tscn directly and press F6 (Run Current Scene) to iterate on island layout, coconut placement, and the time limit without going through the ship each time. Select the Island node to change Time Limit Seconds in the Inspector.

Press F8 to stop and F5 to run again.

No sailing between the ship and the island is included yet: the Gangplank and Rowboat are a placeholder scene swap (get_tree().change_scene_to_file), not real travel, and player position/state does not carry over between the two scenes. The pirate ship is a HUD progress icon, not an actual ship sailing the ocean toward the island. There is no score, lives, or persistence across failed runs. Stations, survival, swimming, procedural ocean, and networking are also not included.
Use separate feature branches and follow docs/team-contract.md for review requirements.

## What each file is for

| File | Purpose |
| --- | --- |
| project.godot | Godot project settings: starting scene, controls, window size, and renderer. Open this to import the project. |
| scenes/main.tscn | Assembles the ship and camera. This is the scene that runs with F5. |
| scenes/ship.tscn | Ship artwork, deck boundary collision, and player instance. |
| scenes/player.tscn | Static player sprite and circular collider, with the movement script attached. |
| scripts/player.gd | The only gameplay script: input, movement speed, and collision-aware movement. |
| scripts/player.gd.uid | Godot-generated stable script identifier. Keep and commit it; do not edit it manually. |
| assets/ship.png | Transparent ship artwork. |
| assets/player_viking.png | Transparent, static player artwork. |
| scenes/island.tscn | Placeholder island: sand shape, camera, boundary collider, player instance, three coconuts, a Rowboat, and the run HUD (coconut count, timer, pirate-ship track, message label). |
| scenes/coconut.tscn | Reusable collectible: placeholder sprite, collision area, and a "collected" signal. |
| scripts/coconut.gd | Detects the player, emits "collected", and removes the coconut. |
| scripts/island.gd | Runs the island: coconut count, countdown timer, pirate-ship HUD icon, and win/lose logic. |
| scripts/rowboat.gd | Detects the player reaching the rowboat and defers the win/lose decision to island.gd. |
| scripts/scene_trigger.gd | Reusable walk-over scene-switch trigger, used by the ship's Gangplank. |
| assets/*.png.import | Godot's import settings and resource identities for the images. Keep and commit these alongside the PNGs. |
| icon.svg | Project icon referenced by project.godot. |
| icon.svg.import | Godot's import settings for the project icon. |
| docs/minimal-mvp.md | This guide: how to run, understand, and edit the MVP. |
| docs/team-contract.md | Existing team agreement and pull-request workflow. Not gameplay code. |
| README.md | Existing repository title and team identification, displayed on GitHub. |
| AGENTS.md | Instructions for coding assistants working in this repository. Not loaded by the game. |
| .gitignore | Keeps generated caches, builds, and local editor files out of Git. |
| .gitattributes | Normalizes text-file line endings across teammates' computers. |
| .editorconfig | Shared text-editor formatting settings. |

Godot also creates a hidden .godot folder for imported caches and local editor state.
It is ignored by Git and regenerated when needed; leave it alone during normal work.
The hidden .git folder holds repository history and the GitHub connection. Do not delete it.

The art-generation prompts and optional Web export preset have been removed.
There are no animation or shader files. The Compatibility renderer remains enabled;
a Web export preset can be added later through Project > Export.
